# Непрерывная интеграция

Что запускается, когда, зачем существует и что делать, когда красное. Сам список джобов определён в
[`TESTING.md`](../TESTING.md) §15; этот документ — про эксплуатацию.

## Воркфлоу

| Воркфлоу | Файл | Триггер |
|---|---|---|
| Lint | `.github/workflows/lint.yml` | push, pull request |
| Test | `.github/workflows/test.yml` | push, pull request |
| Determinism | `.github/workflows/determinism.yml` | push, pull request |
| SDK | `.github/workflows/sdk.yml` | пул-реквесты, трогающие `sdk/` |
| Docs | `.github/workflows/docs.yml` | пул-реквесты, трогающие `docs/` |
| Nightly | `.github/workflows/nightly.yml` | по расписанию |
| Release | `.github/workflows/release.yml` | тег `v*` |

## Обязательные проверки

Пул-реквест не вливается без зелёных:

`lint` · `test-fast` (Linux, macOS, Windows) · `test-linux` · `determinism` · `mutation` · `bdd` ·
`fuzz-short` · `docs`, если менялся `docs/` · `sdk`, если менялся `sdk/`.

Ночные джобы — `portability`, `hunting`, `perf`, `fuzz-long` — не блокируют слияние. Они блокируют
**релиз**, и красный ночной джоб разбирается тем же утром: это те джобы, которые замечают, что мы
стали медленнее или хуже находим баги, а покоммитная проверка этого не видит.

## Когда джоб красный

**`lint`.** `make lint` локально — это те же команды. Механические правила
([`ARCHITECTURE.md`](../ARCHITECTURE.md) §8, правило 14) печатают номер правила и нарушающую строку.
Это архитектурные нарушения, а не придирки к стилю, и чинятся они переносом кода, а не отключением
проверки.

**`determinism`.** Вывод называет первое расходящееся событие с обеих сторон. Сид из строки падения
воспроизводится локально через `bohr run --repeat`, и это P1. Регрессия
детерминизма, попавшая в `main`, обесценивает сохранённые пакеты, и мы не узнаем какие.

**`mutation`.** Красный здесь означает, что инъекция **не** сломала набор тестов детерминизма — дыра
в тестах, а не в коде. Чинится усилением теста, никогда — удалением инъекции.

**`fuzz-short`.** Падающий вход выгружается артефактом и попадает в `fuzz/corpus/` тем же коммитом,
что и исправление.

**`perf` (ночной).** Печатает оба числа и базовую линию. Регрессия разбирается до следующей фичи;
первое, куда смотреть, — доля фильтрации ([`PLATFORMS.md`](../PLATFORMS.md) §5).

**`hunting` (ночной).** Поиск перестал доставать до дефекта, до которого доставал. Это настоящая
регрессия при всех зелёных проверках корректности, и обычно она указывает на планировщик, на
целеуказание сбоев или на операторы мутации. Находки, которые кампании всё же дали, прикладываются к
упавшему прогону: первый вопрос всегда — до чего поиск дотянуться *смог*.

## Кеширование и время

Каталоги сборки кешируются на воркфлоу через `Swatinem/rust-cache`. Гостевые программы из
`testdata/` собираются в CI из закоммиченных исходников с зафиксированными флагами и кешируются по
хешу исходников — никогда не коммитятся бинарниками ([`TESTING.md`](../TESTING.md) §13).

Бюджет: блокирующий набор укладывается в 20 минут. Если он вырастет — работа переезжает в ночные
джобы, а не удаляется: набор, которого перестают ждать, — это набор, который перестают читать.

## Права на раннерах

L3 и выше требуют `ptrace` и пространств имён пользователей. Раннеры GitHub на Ubuntu дают и то и
другое. Контейнерные джобы запускаются с `--cap-add=SYS_PTRACE --security-opt seccomp=unconfined`
([`PLATFORMS.md`](../PLATFORMS.md) §3).

Аппаратных счётчиков переходов на хостед-раннерах нет, поэтому `determinism` идёт там с
гранулярностью системных вызовов. На собственном ночном раннере они есть, и `portability` — то место,
где две гранулярности сверяются между собой.

## Секреты

В CI ровно один секрет: токен реестра для релизного воркфлоу. Нет ни эндпоинта телеметрии, ни
краш-репортера, ни аналитики. Пул-реквесты из форков секрет не видят, а релизный воркфлоу
запускается только на тегах этого репозитория.
