# Метки

Одна таксономия для задач и пул-реквестов. У каждой задачи минимум одна метка `A-` и одна `C-`;
`P-` ставится при разборе.

## `A-` область

| Метка | Область |
|---|---|
| `A-tape` | лента энтропии, ABI выборок, журнал |
| `A-backend` | граница бэкенда и её реализации |
| `A-ptrace` | конкретно бэкенд системных вызовов: seccomp, пространства имён, `prctl` |
| `A-kernel` | логические часы, планировщик, цикл прогона |
| `A-world` | виртуальные сеть, диск, жизненный цикл узлов |
| `A-explorer` | мутации, корпус, покрытие, целеуказание сбоев |
| `A-reducer` | дельта-отладка, минимизация |
| `A-trace` | журнал событий, формат пакета, отпечаток |
| `A-report` | текстовый, JSON и HTML-вывод |
| `A-sdk` | любой из пяти SDK |
| `A-cli` | команды, флаги, коды выхода |
| `A-docs` | всё в `docs/`, включая русское зеркало |
| `A-ci` | воркфлоу, раннеры, кеширование |

## `C-` категория

| Метка | Значение |
|---|---|
| `C-bug` | что-то работает неправильно |
| `C-determinism` | **расхождение или источник недетерминизма.** Всегда вместе с `P-critical` |
| `C-feature` | новая возможность |
| `C-perf` | скорость или память |
| `C-refactor` | без изменения поведения |
| `C-docs` | документация |
| `C-test` | покрытие тестами или тестовая инфраструктура |
| `C-syscall` | неподдержанный системный вызов, нужный реальной мишени |

`C-determinism` отделена от `C-bug` намеренно: это класс, который обесценивает сохранённые пакеты и
подрывает саму посылку продукта, и он должен фильтроваться в один клик.

## `P-` приоритет

| Метка | Значение | Реакция |
|---|---|---|
| `P-critical` | детерминизм сломан, потеря данных в пакете или ложное «воспроизводится» | бросаем всё |
| `P-high` | блокирует гейт этапа | на этой неделе |
| `P-medium` | обычная работа | по плану |
| `P-low` | хорошо бы | когда всплывёт |

## `S-` статус

`S-needs-triage` · `S-needs-repro` (нужен сид или пакет) · `S-blocked` (со ссылкой на блокер) ·
`S-needs-decision` (открытый вопрос из [`ARCHITECTURE.md`](../ARCHITECTURE.md) §14).

## Для контрибьюторов

`good-first-issue` — маленькая, самодостаточная, с названным в теле файлом. ·
`help-wanted` — нужно, и этим никто не занят. · `E-easy` / `E-medium` / `E-hard` — оценка
сложности: `E-easy`, которая занимает неделю, уводит взявшегося за неё не туда.

## Этапы

Задачи привязываются к `M0`–`M6` из роадмапа. Задача вне этапов — это либо
бэклог, либо кандидат на закрытие; бэклог, притворяющийся планом, — это то, как растёт объём.
